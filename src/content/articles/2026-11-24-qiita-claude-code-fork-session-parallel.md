Claude Code（クロード・コード）は、AI企業Anthropicが提供する、ターミナル（コマンド入力画面）で動くAIコーディングツールです。この記事は、合同会社ジョインクラスがQiitaに書いた実践レポートの要約です。同社は毎日30本ほどの自動ジョブから `claude -p` を呼び出し、部署ごとの仕事をAIに任せているといいます。

## 何に困っていたのか

長い会話で調べものをした後に「A案とB案を両方試したい」と思っても、会話の流れは1本しかありません。A案を試して失敗すると会話がA案の試行錯誤で埋まり、B案に戻るころには最初に集めた前提が自動要約で薄まってしまう――これを解決するのが、セッションの分岐（fork）です。

## 1. 対話中に分岐する

Claude Codeとの会話中に `/fork` と打つと、そこまでの会話を引き継いだ別のセッションができ、元のセッションもそのまま残ります。

```text
（調査が終わった時点で）
> /fork
→ 分岐先でA案を試す

（別ターミナルで元セッションを再開）
$ claude --resume
→ 一覧から元のセッションを選び、B案を試す
```

コツは「分岐する前に前提を会話に出し切っておく」ことです。分岐後に片方で読んだファイルは、もう片方には入りません。

### 落とし穴：作業フォルダーは共有される

分岐するのは会話であって、ファイルではありません。著者は、A案で直したスクリプトをB案のセッションが古い内容で書き戻してしまったことがあるそうです。ファイルも分けたいときは、同じリポジトリを別フォルダーに展開できる `git worktree` を併用します。

```bash
git worktree add ../one-ceo-planB -b try/plan-b
cd ../one-ceo-planB
claude --resume <元のセッションID> --fork-session
```

## 2. スクリプトから分岐する

スクリプトでは `--resume` に `--fork-session` を付けます。付けないと元のセッションに追記されてしまい、付けると新しいセッションIDで分岐します。記事では、まず `--session-id` で決めたIDのセッションに前提だけを集めさせ、そこから2本を同時に分岐させてA案・B案を出させる例を紹介しています。確認方法は、結果JSONの `session_id` が互いに違い、元のIDとも違うことです。

## 3. 無人ジョブでは分岐できなかった

同社の自動ジョブは、会話の記録が1日約200MB溜まっていたため `--no-session-persistence`（記録を残さない設定）を付けていました。そのため、夜間ジョブが変な結論を出しても、その時点から分岐して別の指示を試せず、丸ごと再実行するしかなかったといいます。

そこで、環境変数 `CLAUDE_KEEP_SESSION=1` を付けたジョブだけ記録を残し、セッションIDをログに書き出すように変更しました。あとからそのIDで `claude --resume "$SID" --fork-session` を実行すれば、「この判断の根拠を出して」と分岐先で問い直せます。

## 落とし穴まとめ

- `--resume` でセッションが見つからない → 記録を残さない設定になっていないか確認
- 分岐したのに元に追記された → `--fork-session` の付け忘れ
- 2案のファイル変更が上書きし合う → `git worktree` で作業場所を分ける
- 別フォルダーで再開すると見つからない → セッションはフォルダー単位で保存される
- パイプ越しだと失敗が成功に化ける → `PIPESTATUS` でclaude側の終了コードを見る

著者は「迷ったら両方試す」ができるようになった一方、比べる基準と片方を捨てる手順を先に決めておくことが大事だとまとめています。
