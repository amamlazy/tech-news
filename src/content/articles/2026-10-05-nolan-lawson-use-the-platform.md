## 何が書かれているか

Web 標準やパフォーマンス、アクセシビリティの分野で「use the platform（プラットフォームを使え）」と訴えてきた Nolan Lawson 氏が、あえて反対側の視点からその理由を掘り下げている。

まず歴史的な経緯として、長い間ブラウザがエコシステムに追いつく立場で、jQuery のようなライブラリが穴を埋めてきたことを挙げる。次に習慣の問題で、npm で React コンポーネントを探すことに慣れていると、CSS の `position: sticky` で済む問題にもパッケージを探してしまう。さらに、npm パッケージの README は丁寧なのに、プラットフォームのドキュメントは長く散らばっていたという差も指摘している。

## 自分で作るのは楽しい

氏が特に掘り下げるのは「自分で作るほうが楽しい」という動機だ。モーダルダイアログを例に、配置、背景のスクロール、Esc での閉じる操作、フォーカストラップと作り込んでいく過程は学びが多く、出来上がったものには愛着が湧く。`<dialog>` を使えば済むと分かっていても手放しにくい、いわば IKEA 効果だと述べる。

## AI はどちらに働くか

AI コーディングについては楽観と悲観の両方を示している。LLM はプラットフォームの知識が豊富なので最適な標準 API を選べるかもしれないし、開発者が自分で書かない分 IKEA 効果も消える。一方で、既存のヘルパーを無視して同じようなコードを何度も書く傾向があり、十分なテストをせずに最初の案をそのままコミットすれば、標準から外れた独自コードが急増するおそれもあるという。

## 現場で見るところ

エージェントに UI を作らせるときも、`<dialog>` や Popover API など標準機能を優先するよう指示やルールに書いておくと、保守するコードの量を抑えやすい。
