## どんな記事か

songchong 氏が10月6日に Qiita に公開した調査記事（完全版は筆者のサイトに掲載）。Claude Code、Codex、Gemini CLI、GitHub Copilot、Cursor の5つの AI エージェントについて、API キーを渡す6つの方法がそれぞれどこまで安全かを、各社の公式ドキュメントに沿って整理している。

## 6つの渡し方

- **チャットに貼る**: キーはベンダーに送られ、手元の会話ログにも残る。Claude Code はログを暗号化せずに保存し、Copilot CLI は既定で GitHub アカウントに同期する
- **.env ファイル**: AI が一度読めば、その内容は会話に入る。Gemini CLI は .env を自動で読み込む。除外設定が止めるのは AI 自身の読み取りツールだけで、Claude Code は `cat .env` も止めるが、`grep -r` やスクリプト経由は通ってしまう。Cursor の .cursorignore はターミナルを対象にしていない
- **環境変数**: AI からは直接見えないが、AI が実行するコマンドには引き継がれる。Codex は既定ですべてを渡す（`shell_environment_policy` で制限できる）。Copilot CLI や Claude Code にも制限する設定がある。Gemini CLI では、環境変数を外に持ち出せることが Tracebit によって実証された
- **MCP の設定ファイル**: キーを直書きせず、環境変数を参照させる。Astrix の調査では、公開されている MCP サーバーの53%が長期間使える固定のキーを使い、OAuth は8.5%だった
- **OAuth**: 最も安全な方法で、外部の MCP については5つのツールすべてが対応している（Copilot のクラウドエージェントを除く）
- **クラウドのシークレットストア**: Claude Code と Codex のクラウドエージェントは、本物のキーをエージェント自身に持たせない

## 筆者の勧める順番

筆者は次の順で対策することを勧めている。

1. キーをチャットに貼らない
2. 権限を絞ったキーを作る
3. 使えるなら OAuth を選ぶ
4. 除外設定とサンドボックスを組み合わせる
5. 漏れたらすぐにキーを無効にする

## 現場で見るところ

「.env を除外設定に入れたから大丈夫」と考えている人ほど、抜け道を知っておく価値がある。チームでエージェントを使うなら、使っているツールごとに環境変数の受け渡し設定と会話ログの保存先を一度確かめておきたい。
