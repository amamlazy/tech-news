## 何が変わったか

GitHub は、2026年4月27日に始めた GitHub App インストールトークンのステートレス形式への段階的移行を完了したと発表した。今後新しく発行されるインストールトークンは、既定で `ghs_APPID_JWT` 形式になる。発行と検証が速くなり、GitHub API の信頼性向上につながるという。

トークンは引き続き `ghs_` で始まるが、長さは従来の40文字から約520文字に伸びる。権限、リポジトリのスコープ、1時間の有効期限、トークン発行用の REST エンドポイントは変わらない。変更前に発行されたトークンは期限まで使える。

## 期限

新形式を試すために用意されていた一時ヘッダー `X-GitHub-Stateless-S2S-Token` は2026年11月30日に廃止される。それ以降はヘッダーが無視され、対象アプリは常にステートレス形式のトークンを受け取る。本番コードからこのヘッダーを外しておく必要がある。

## 現場で見るところ

GitHub はトークンを不透明な文字列として扱うよう求めている。具体的には次の点を確認したい。

- トークンが40文字であることを前提にしたバリデーションや正規表現
- 長さ上限が小さい DB カラム、シークレットストア、環境変数
- 長い Authorization ヘッダーを切り詰めたり拒否したりするプロキシやゲートウェイ
- 旧形式のパターンにしか一致しないログのマスキング規則
