Messages API（メッセージズ・エーピーアイ）は、企業や開発者が自分のアプリからClaudeを呼び出すときの「窓口」で、Anthropic自身のClaude Codeなどもここを通っています。Rust（ラスト）は、速くてメモリの扱いが安全なことで知られるプログラミング言語です。

## 何が投稿されたか

Anthropicは日本時間11月26日未明、「Messages APIをPythonからRustに移行した。既存のサービスを使って新しいサービスを検証し、Claudeエージェントのチームが2つの版の違いを突き止めて直した方法をブログで紹介する」と投稿しました。取得時点でいいね6,980件、リポスト473件、表示約149万回です。

## ブログの中身

ブログによると、API通信量は2024年初めから2026年秋までに約1,800倍に増え、Pythonでは処理のたびに余分な負荷がかかるようになっていました。一部だけをRustにする方法では、CPU使用量は8〜10％しか減らず、かえって複雑になったといいます。2026年5月時点で、Anthropicがマージするコードの80％以上をClaudeが書いていたこともあり、丸ごと書き換えに踏み切りました。

Claudeは主要な処理の最初の版を約1週間で書きましたが、難しかったのは「新旧が同じ動きをしているか」の確認でした。約700件の結合テストには4月時点で約98％合格していたのに、本番の通信で比べると一致したのは約4分の1だけだったそうです。

そこで、本番のリクエストを新旧両方に流して結果を比べる「シャドーイング」の仕組みを作り、違いが見つかるとClaudeのエージェントが自分の砂場（サンドボックス）で原因を推測・再現し、修正案を出す流れにしました。人間は修正案のレビューに集中し、過去の指摘は「メモリ」として次のエージェントに引き継がれます。結果として、リクエストあたりのCPU使用量を約70％、最初の文字が返るまでの時間（中央値）を約20％減らし、サービスを止めずに移行できたとしています。

## 日本からの反応

Claude Code関連の著書があるoikon氏は「Rustへの移行の話も興味深いけど、Inner/Outer/Memory Loopの組み方の話が参考になる」と投稿しています。
