Agent Harness（エージェント・ハーネス）とは、AIモデル（LLM）の外側にあって、モデルの出力を「ファイルを読む」「コマンドを実行する」といった実際の行動につなげる仕組みのことです。「Agent = LLM + Harness」とも表現されます。この記事は、yamamoto_a_genee氏がQiitaに書いた、ハーネスを自作して確かめた実践レポートの要約です。

## なぜ作ってみたか

著者は、同じLLMを使っているのにツールによって精度や使い勝手が違うのはなぜか、という疑問から出発します。その理由の一つがハーネスで、OSにたとえるならLLMがCPU、ハーネスがファイル管理や権限管理を担うOSに近い、と説明しています（あくまで理解のための比喩だと断っています）。

## 作ったもの

Python 3.12で動作確認し、3.10以上が必要です。実モデルとの接続にはAnthropic SDKを使い、ハーネスの基本ロジックは標準ライブラリだけで書いています。用意したツールは `read_file`、`write_file`、`run_command` の3つです。

- `safe_path()`：シンボリックリンク経由も含め、ワークスペースの外へ出るパスを拒否
- `run_command`：シェルを使わない（パイプや `&&`、`cd` は使えない）。`python -m unittest` 以外のコマンドは実行前に人が承認
- `truncate()`：出力は4000文字まで。エラーは末尾に出やすいので末尾を残す
- `log()`：各ステップをJSON Lines形式で `trace.jsonl` に追記。書き込んだファイルの中身は記録しない
- 最大15ステップ、コマンドは60秒でタイムアウト

APIキーがなくても確かめられるよう、決まった応答を順番に返す偽のクライアント（FakeClient）でループや終了条件をテストする `test_harness.py` も用意しています。実モデルで動かすときは `pip install anthropic` のあと、`ANTHROPIC_API_KEY` と `ANTHROPIC_MODEL` を設定して `python3 harness.py` を実行します。

## はまったところ：Pythonのキャッシュ

テスト中、ソースを直したのに古い結果が出ることがありました。原因はPythonのバイトコードキャッシュ（.pyc）で、更新時刻とファイルサイズで有効かを判断するため、同じ秒に同じサイズで書き換えるなど条件が重なると古いキャッシュが使われます。

`PYTHONDONTWRITEBYTECODE=1` はキャッシュの「書き込み」を止めるだけで、既存の.pycの「読み込み」は防げませんでした。そこで、コマンド実行のたびに一時ディレクトリを作って `PYTHONPYCACHEPREFIX` に指定し、古いキャッシュを再利用しないようにしています。著者は、モデルから見えるのは「テストが失敗した」という結果だけなので、実行環境が古いコードを読んでいるとモデルは見当違いの原因を探し始める、と指摘します。

## 著者の結論と注意点

- 承認や許可リストは便利だが、それだけでは安全の境界にならない。信頼できないコードは隔離環境で動かす
- 1回のAPI呼び出しで済むならハーネスは不要。複数ツール・複数ステップ・検証・人の承認などが必要になってから足す
- 「モデルが動かない」と思ったら、モデル以外の層を疑い、変える要素を一つずつ切り分ける。そのためにもログやトレースが大切

ハーネスの改善でベンチマークのスコアが上がったという数字も紹介していますが、一次情報を確認できていない二次情報だと明記している点も、丁寧なレポートです。
