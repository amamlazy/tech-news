TLA+（ティーエルエープラス）は、システムが「どんな順番で操作されても守るべき決まり」を書き、それが破られる場面をコンピューターにしらみつぶしに探させる「形式検証」のための言語です。Quint（クイント）は、同じ考え方をTypeScriptに近い書き方でできるようにした言語です。この記事は、karamage氏がZennに書いた、Quintを実際に動かして考えを確かめた記事の要約です。

## 問題意識：「自作自演の満点」

実装を書いたのも、レビューしたのも、テストを書いたのも同じAI。全部グリーンでも、それは生徒が自分で問題を作って自分で丸をつけるようなもので何も保証しない、と著者は指摘します。何が「正しい結果」かをどう決めるかという「テストオラクル問題」は昔からある課題で、別のモデルに敵対的にレビューさせても、47件の細かい指摘のなかで本命のバグは見逃されたといいます。

## 例：AIが書いたチケット販売コード

確認画面で在庫を表示し、確定ボタンで在庫を1つ減らす実装をAIに書かせると、確定時に在庫を再確認しないコードが出てきました。AIが書いたテスト3本（在庫があれば買える、なければ売り切れ、2人が順番に買う）は全部パスしますが、どれも「1人ずつ順番に」しか試していません。

## ルールを書いて機械に探させる

Quintでは、状態、初期状態、起こりうる操作（誰かが確認する／確定する）を書き、最後にルールを1行置きます。

```
val noOversell = sold <= INITIAL_STOCK
```

```bash
npm i @informalsystems/quint -g
quint run ticket.qnt --invariant=noOversell
```

`quint run`は操作の順番をランダムに何千通りも試し、12ミリ秒で違反を見つけました。2枚しかないチケットを3人に売り、在庫が-1になるまでの手順も全部表示されます。bobが確認したあと、確定する前にcarolが最後の1枚を買う、という割り込みです。

確定時に在庫を再確認するよう直したあとは、`quint verify ... --backend=tlc`で起こりうる状態をすべて調べ、3人・2枚の世界の29通りの状態に違反がないことを確認しています。

## 実装そのものを検査する

`quint run --mbt --n-traces=1000`でありうる操作手順を1000本JSONに書き出し、その手順どおりに実際のTypeScript実装を動かして状態がQuintと一致するかを比べるテストを1本だけ書きます。AIの元の実装では1000本中578本で不一致が見つかり、修正後は0本になりました。

## 著者の結論

人間の仕事は「問題を作ること」から「採点基準（ルール）を決めること」に変わる、ただし採点基準だけはAIに任せてはいけない、と著者は述べます。Quintには Claude Code などのAIエージェント向け公式スキルがあり、コードをQuintに書き起こす作業はAIに手伝わせられます。それでも、読めば挙動が分かるテストケースはなくならないとも補足しています。
