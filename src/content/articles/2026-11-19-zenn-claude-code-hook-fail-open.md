Claude Code（クロード・コード）はAnthropicのAIコーディングツールで、「hook（フック）」はAIがコマンドを実行する直前などに、自分で書いたスクリプトを差し込んで確認や拒否ができる仕組みです。この記事は、minewo氏がZennに書いた、自作のhookを検証してみた実践レポートの要約です。

## 何が起きていたか

minewo氏は、`rm -rf` のような危険なコマンドや、`curl ... | sh`（ダウンロードしたスクリプトをそのまま実行する形）を止めるPreToolUse hookを使っていました。ところが後から検証すると、実際にClaude Codeから届く形のデータを流したとき、終了コード0（許可）で素通りしていました。

```
printf '%s' '{"tool_name":"Bash","tool_input":{"command":"rm -rf /"}}' | ./safety.sh
echo $?   # 0（素通り）
```

gitの履歴に残っていた4世代のスクリプトすべてで同じ結果で、「途中で壊れたのではなく、最初から検査できていなかった」といいます。

## 原因は2つ

- **止まるのは終了コード2だけ**：公式ドキュメントによると、PreToolUse hookでブロックになるのはexit 2のときだけ。Unixで「失敗」を表すexit 1などは「止めないエラー」扱いで、コマンドは実行される。hookが途中で異常終了しても止まらない
- **抽出の失敗が「空」として扱われた**：スクリプトはJSONの `data.command` を見ていたが、実際のデータでは `tool_input.command` と1階層深い場所にある。取り出せずに空文字になり、「検査するコマンドが無いなら通す」という行でexit 0になっていた

jqを使って `.tool_input.command // ""` と書いても、壊れたJSONではjqがexit 5で終わって素通りし、配列が来ると空でない文字列になって通ってしまうことも実測で示しています。

## 直し方

minewo氏は「取り出せなかったときにどうするか」を先に決め、次のように直しました。

1. 検査対象がそもそも無いときだけ通し、入力はあるのに取り出せないときは止める（fail-closed）
2. 抽出の失敗を終了コードで返し、「空文字だった」と「抽出に失敗した」を別に扱う
3. `data.command` と `data.tool_input.command` の両方を見る
4. `trap ... EXIT` を使い、意図した `exit 0` 以外の終わり方はすべてexit 2にする（`trap ... ERR` は取りこぼしがあったという）

## 注意点

止める側に倒すと、今度は止めすぎが起きます。実際に直後、worktree環境で誤ブロックが起き、対応したそうです。minewo氏は「止めすぎは気づけるが、素通しは気づけない」として止める側を選び、ブロックされるべきケースと通るべきケースの両方で29件のテストを用意しています。自分のhookも、実際の形のデータを標準入力に流して終了コードが2になるかを見るだけで確かめられる、としています。
