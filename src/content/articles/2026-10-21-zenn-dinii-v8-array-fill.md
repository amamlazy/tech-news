V8は、Google ChromeやNode.jsの中でJavaScriptを実行しているエンジンです。この記事は、ダイニーのエンジニア、Riya Amemiya氏が、V8のソースコードに自ら手を入れて配列のメソッドを高速化した、その実装を解説したハンズオン型のレポートです。

## fillとは

`fill(value, start, end)`は、配列の`start`から`end`までを同じ値で上書きするメソッドです。

```js
[1, 2, 3, 4, 5].fill(0);       // => [0, 0, 0, 0, 0]
[1, 2, 3, 4, 5].fill(9, 1, 4); // => [1, 9, 9, 9, 5]
```

## 何が遅かったのか

筆者によると、パッチ前の実装は範囲内のすべての位置で`SetImpl`という汎用の書き込み処理を呼んでいました。`SetImpl`は配列の種類ごとの分岐や値の変換、GC（不要なメモリを片付ける仕組み）への通知などを担うので、どんな配列でも正しく動きます。

しかし`fill`では書き込む値がループ中に変わりません。10万要素なら、同じ変換と分岐を10万回くり返していたことになります。筆者はこれを「ループ不変な処理を要素数回だけやり直している」ボトルネックだと説明しています。

## どう直したか

配列の種類（ElementsKind）ごとにやり方を分けました。

- **小さな整数（Smi）**：Smiは値をそのままスロットに埋め込める形式なので、`MemsetTagged`で連続した領域を一気に埋める。GCへの通知も不要
- **小数（double）**：値を`double`に変換する処理を1回だけ行い、あとは単純なループで書き込む
- **オブジェクト**：各スロットがメモリ上の別の場所を指すため、GCへの通知（write barrier）が必要。単純なメモリ埋めは使えないので従来通り

## 結果

arm64のリリースビルドで、10万要素の配列を使った計測です。

| ケース | 変更前 | 変更後 | 倍率 |
| --- | --- | --- | --- |
| 整数で全体を埋める | 34.67µs | 5.07µs | 約6.8倍 |
| 穴あき整数配列を埋める | 36.46µs | 4.96µs | 約7.4倍 |
| 小数で全体を埋める | 51.37µs | 10.10µs | 約5.1倍 |
| オブジェクトで埋める | 55.6µs | 55.6µs | 約1.0倍 |

16要素の小さな配列では約1.3倍と、効果は大きな配列ほど目立ちます。

## 読みどころ

V8への貢献というと難しく聞こえますが、記事の核は「ループの中で毎回同じことをしていないか」という、普段のコードにも当てはまる考え方です。記事には計測に使ったスクリプトも全文載っているので、性能改善の進め方の手本としても読めます。
