Claude Codeは、Anthropicが提供する「AIにプログラミング作業を任せられる」ツールです。作業を裏側で並行して進める「バックグラウンドエージェント」を複数動かせますが、その状況表示のために、思った以上にトークン（AIの利用量の単位で、料金や利用上限に直結するもの）を使っているという分析が出ました。

## 何が分かったのか

GIGAZINEによると、AIツール開発元のFlamerix AIがOpenTelemetry（動作の記録を外部に出す仕組み）のデータを分析したところ、「エージェントサマリー」機能がClaude Code全体のトークン消費の約15〜20%を占め、APIリクエストの約5件に1件がこの機能のためだったといいます。Opusモデルを使う場合は18〜26%に達したとしています。

仕組みはこうです。Claude Codeは約30秒ごとに、すべてのバックグラウンドエージェントについて会話記録（トランスクリプト）全体をそのエージェント自身のモデルに送り、「直近の行動を3〜5語で説明して」と頼みます。返ってきた答えは、エージェントパネルのステータス行の更新にしか使われません。この機能は2026年8月のバージョン2.1.232以降で既定で有効になっており、設定で止めることはできないとのことです。

## 回避策とその注意点

Flamerix AIは、約70行のBun用スクリプト「no-agent-summary.js」を公開しました。setTimeout()（一定時間後に処理を実行する関数）を包み込み、エージェントサマリー用のタイマーだけを止める仕組みで、Claude Code本体は書き換えません。ただし、Claude Codeの更新で目印となる文字列が変わると効かなくなるため、更新のたびに確認が必要です。

一方、Claude Code研究所（運営：Arrowheads）は、目印の変更に加え、環境変数「BUN_OPTIONS」を使うためマシン上のすべてのBunに読み込まれてしまう点などを挙げ、このスクリプトの利用は「勧めない」としています。

## 読みどころ

「なぜか利用上限にすぐ達する」と感じていた人には、原因の1つになりうる話です。非公式の回避スクリプトはリスクもあるので、まずはバックグラウンドエージェントを必要以上に並べない、といった使い方の見直しから考えるのが無難そうです。
