Git（ギット）は、プログラムの「いつ・誰が・どこを変えたか」を記録するための道具です。この記事は、その仕組みを法律に当てはめて、日本の法令がどう改正されてきたかを“変更履歴”として読めるようにした、個人エンジニアによる体験記（ハンズオン記事）です。

## 何を作ったのか

Zennに記事を書いたkoheiさんは、日本の全法令をGitリポジトリ（変更履歴付きの保管場所）にした「houritsu」を公開しました。記事によると、規模や作りは次のとおりです。

- 法令ファイルは**8,982本**、mainブランチの**コミット（変更の記録）は23,338件**
- **1コミット＝施行された1回の改正**で、コミットの日付は施行日
- 条文はMarkdown（見出しなどを記号で表す書式）に変換し、先頭に法令の情報（frontmatter）を付ける
- まだ施行されていない改正は「upcoming」ブランチで管理
- 元データはe-Govの「法令API v2」から毎日自動で取り込み、変換ツール「houritsu-builder」はRustで作成

## どう使うのか

たとえば個人情報保護法の改正の歴史は、次のコマンドで一覧できます。

```
git log --format='%ad %s' --date=short -- laws/act/415/415AC0000000057.md
```

差分（変更点）を見れば、「日本学術会議」に関する規定が追加されたことや、「三年ごとに」が「三年を目途として」に書き換わったことなどが一目で分かると紹介されています。コミットメッセージには改正法の番号や公布日、法案のURL（Bill-Url）も入っており、`git log -L`を使えば特定の条文だけの変遷を追うこともできます。11月3日には、法案の提出者を記録する「Bill-Submitter」の情報も追加したそうです。

## 注意点と工夫

筆者は限界も正直に書いています。

- 履歴がさかのぼれるのはおおむね2015年ごろから
- `git blame`（各行を最後に変えたのは誰か調べる機能）で分かるのは、その文言が最初にできた日ではない
- 正式な法令の内容は、あくまで官報で確認する必要がある

また、Gitは1970年より前の日付でコミットを作れないため、317件のコミットは日付を1970年1月2日にそろえ、本当の施行日は「Enforced」という追記欄に残しています。最も古いのは1872年11月9日の「改暦ノ布告」だそうです。データはCC BY 4.0、変換ツールはMITライセンスで公開されています。

## 読みどころ

「法律の改正を差分で読む」という発想そのものが面白く、エンジニアの道具が法律の世界でも役立つことを示しています。次は国会の議事録を扱う「kokkai-cli」のアイデアもあるそうです。窓の杜でも取り上げられ話題になりました。
