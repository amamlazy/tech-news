オープンソースのメンテナー（無償で公開されているソフトを管理・保守している人たち）は今、AIが自動で見つけた「セキュリティ上の問題かもしれないもの」の報告に追われています。中には重複や、そもそも問題ではないものも多く、対応の負担が大きくなっています。今回の試みは、その状況を変えようとするものです。

## 何が投稿されたか

GitHubの公式アカウントは日本時間11月18日未明、「メンテナーに必要なのは修正であって、AIのバグ報告の追加ではない。@msftsecurityと一緒に、9,791件の生のAIセキュリティ検出結果を、6つのオープンソースプロジェクト向けの、修正案付きで検証済みの非公開報告99件に変えた。メンテナーはすでに修正を出している」と投稿しました。午前3時56分ごろの投稿は、取得時点でいいね49件、リポスト10件、表示9,383回です。

## ブログに書かれた進め方

GitHubのブログによると、パイロットは「Codename MDASH」と呼ばれ、次の流れで進めました。

1. **見つける**：Microsoft SecurityのAIシステムMDASHが、MicrosoftのAIモデル「MAI Cyber」で各プロジェクトを調べ、修正案も作る
2. **絞り込む**：GitHub Security LabのAIの仕分け役が、重複を除き、本当に問題かを確かめ、影響の大きいものに絞る
3. **非公開で報告**：GitHubの非公開の脆弱性報告機能で、再現コードと修正案付きで届ける
4. **直す**：何をどう、いつ直すかはメンテナーが決める

AIの仕分けのあと、Microsoftの研究者7人が手作業で確かめ、届いた報告は99件でした。11月15日時点で55件が修正され、そのうち14件はすでにリリースに含まれています。

## メンテナーの声

Webサーバー「Caddy」のメンテナーは、受け取った22件すべてを1週間以内に修正しました。2人で保守している画像処理ソフト「ImageMagick」では、要点がまとまった報告のおかげで15分で修正できた例もあり、「普段は1件の勧告を読んで理解し直すのに平均30分〜1時間かかる」とコメントしています。Nettyのメンテナーは「脆弱性の発見はもはやボトルネックではない。修正こそが難しい」と述べています。

## 残る課題

一方で、研究者7人が1プロジェクトあたり約2日かけて手で確かめており、このやり方はまだ大規模には広げられないとしています。GitHubは、AIで脆弱性を探す人に向けて「送る前にすべての検出結果を確かめ、非公開で報告すること」を求めています。
