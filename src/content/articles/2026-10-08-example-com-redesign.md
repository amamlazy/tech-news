## 何が変わったか

ドキュメントやサンプルコードでおなじみの「example.com」が、2026年9月28日に大きくリニューアルされた。GIGAZINE によると、長年ほぼ変わらない簡素なページとして知られてきたが、新たに複数言語の説明文やアイコンが加わった。管理する IANA は、変更の理由を「通信量を抑えつつページの有用性を高めるため」と説明している。

example.com、example.net、example.org は、1999年の RFC 2606 で説明用に予約されたドメインだ。説明資料に実在する第三者のドメインをうっかり書いてしまう問題を避けるためのもので、自由に使ってよい。

## 新しいページの作り

9月28日の更新では、英語、アラビア語、中国語、フランス語、ロシア語、スペイン語の説明文を JavaScript で5秒ごとに切り替える仕組みが入った。各文字を個別の要素にして表示のタイミングを少しずつずらし、なめらかに切り替わるアニメーションも付いていた。ただし10月3日にはアニメーションが外され、各言語の説明文を最初からまとめて表示する形に変わっている。

情報が増える一方で、IANA は example.com に来る大量の自動アクセスにも配慮した。基本のページ本体は小さく保ち、追加の内容は別の JavaScript ファイルに分けた。自動アクセスの多くは JavaScript まで取りに来ないので、サーバーが送るデータ量を抑えられるという。

## IANA の注意書き

example.com へのアクセスが多い理由の一つは、サンプルの設定をコピーしたときに example.com の書き換えを忘れることだ。疎通確認や HTTP リクエストの試験先として直接使う開発者もいる。IANA は、example.com の HTTP サービスは本番用途や監視用途のために提供しているものではなく、利用者への案内として運営しているだけだと明記している。2024年9月には POST、PUT、DELETE、PATCH への対応をやめ、「405 Method Not Allowed」を返すようにした。

## 現場で見るところ

ヘルスチェックや CI のネットワーク疎通確認の宛先に example.com を使っているなら、ページの中身や応答が変わる前提で見直したい。テスト用の宛先は自分で管理するエンドポイントにするのが安全だ。
