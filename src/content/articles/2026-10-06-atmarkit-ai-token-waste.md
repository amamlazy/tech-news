## 何が書かれているか

＠IT の連載「API から読み解く AI の裏側」の第3回で、Postman の草薙昭彦氏が AI エージェント運用のコストを取り上げている。記事によると LLM のトークン単価は2025年から2026年にかけておよそ8割下がったが、企業の LLM API 支出は増え続けている。安くなった分だけ検索や長い文脈、多段のツール呼び出しを気にせず増やしてしまうためで、筆者はこれを価格ではなくガバナンスの問題だと位置づける。

## なぜトークンが膨らむのか

エージェントは計画、ツール呼び出し、結果の読み込み、計画の練り直しというループを回すため、1つのタスクでモデルを数十回から200回近く呼ぶこともある。記事は、エージェント型のワークフローは通常のチャットの約4倍、複数エージェントの構成では約15倍のトークンを使うという調査を紹介している。大きなシステムプロンプトを毎ターン送り直すと、費用は回数に比例するのではなく二次関数的に増える。

MCP も要因になる。GitHub の公式 MCP サーバはツール定義を並べるだけで約4万2000トークンを使い、複数のサーバをつなぐと、仕事を始める前にコンテキスト枠の3〜5割が埋まるという。文脈が長くなると精度も落ち、似た名前のツールを取り違えやすくなる。

## 現場で見るところ

筆者は、OpenAPI 仕様から機械的に200個のツールを作るのではなく、エージェントが実際に使う操作を「顧客を照会する」のような意図の単位で10〜30個に絞るよう勧めている。社内で MCP サーバを公開している場合は、ツール数と定義の長さを一度測ってみる価値がある。記事の続きは会員登録（無料）で読める。
