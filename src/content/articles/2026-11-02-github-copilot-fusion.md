GitHub Copilot（コパイロット）は、プログラムを書くときにAIが提案や修正をしてくれるGitHubのサービスです。今回の「Copilot Fusion」は、どのAIモデル（AIの頭脳にあたる部分）を使うかを、Copilotがタスクに合わせて自動で選び、必要なら複数を組み合わせてくれる機能です。

## 何が発表されたのか

GitHubは、10月28日と29日に米サンフランシスコで開いた年次イベント「GitHub Universe 2026」で、Copilot Fusionの正式リリースを発表しました。Publickeyによると、Copilot Fusionは推論、コード生成、デバッグ、ツールの利用など、タスクごとに必要な能力を評価し、AIモデルをどう組み合わせるかを判断します。開発者がモデル選びを自分で管理する負担を減らし、性能とコストのバランスを取りやすくするのが目的です。

## 3つの使い分けパターン

- **Single（シングル）**：選んだ1つのモデルで課題を解く
- **Cascade（カスケード）**：まず効率のよい（安い）モデルが案を作り、品質確認用のモデルが検証して、より能力の高いモデルに任せるべきかを判断する
- **Critique（批評）**：1つのモデルが下書きを作り、別のモデルファミリーのモデルが独立してレビュー。指摘があれば、下書きを作ったモデルが1回だけ直す

## コストと品質の「負荷レベル」

- **Fusion Standard**：コスト・品質・待ち時間のバランス型。日常の作業向け
- **Fusion High**：複数ファイルにまたがる変更など、範囲がはっきりした大きめのタスク向け
- **Fusion Max**：トークン（AIが処理する文字の単位で、料金の基準）の効率も考えつつ、最も深い推論が必要なタスク向け
- **Fusion Fast**：速さが必要な場面で選ばれる。ユーザーは指定できない

また、パブリックプレビュー（試験提供）として、Fusion Standardではローカルにインストールした「MAI Code 1.1 Flash」や「Qwen3.8 Flash Next」モデルを選んで実行することもできます。

## 読みどころ

「どのモデルを使えばいいか分からない」という悩みを、ツール側が肩代わりしてくれる流れです。安いモデルで下書きし、必要なときだけ高いモデルを使う「Cascade」は、料金を抑えたい個人開発者にも気になる仕組みと言えそうです。
