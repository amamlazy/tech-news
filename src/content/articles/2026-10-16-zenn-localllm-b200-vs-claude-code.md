ローカルLLMとは、公開されているAIモデルを自社のサーバーで動かして使う方法です。コードやデータを社外のAIサービスに送らずに済むのが利点で、この記事はokawa2929氏が「社内でClaude Codeの代わりになるか」を、実際にGPUを借りて試した体験記です。

## 組んだ構成

GPUはデータセンター向けのNVIDIA B200（メモリ180GB）を、時間単位で借りられるRunPodで1枚用意しました。モデルを動かすソフトには、多人数の同時リクエストに強いvLLMを選び、コーディングエージェント（ファイルを読み書きしコマンドを実行してコードを直すAIツール）には無料のOpenCodeを使っています。手元のMacBook ProからはSSHのトンネルでvLLMにつなぎました。

```
ssh -N -L 18000:127.0.0.1:8000 -p <ポート番号> root@<サーバーのIPアドレス>
```

モデルは、MoE（多数の「専門家」の一部だけを使って計算し、大きさの割に速く動く作り）の `Qwen3.5-122B` と `gpt-oss-120b` です。Qwenは元のままだと約244GBでB200に載らないため、数値を粗く丸めてファイルを小さくする「量子化」を施した、開発元配布のFP8版（約127GB）を使いました。残りのメモリは、会話の計算結果を取っておくKVキャッシュに回ります。

情報を社内にとどめるため、OpenCodeの `opencode.json` では接続先をvLLMだけにし、共有と自動更新をオフ、Web取得とWeb検索を禁止しています。ただしOpenCodeは起動時にモデル一覧を外部から取りに行き、vLLMも初期設定で利用状況を送るため、本番では `OPENCODE_DISABLE_MODELS_FETCH=1` と `VLLM_NO_USAGE_STATS=1` で止めておくと安心だと書いています。

## 結果

- **精度**：FlaskやClickなど6つのPythonライブラリで実際にあった小さな修正を課題に、各3回・計18回解かせたところ、Qwen3.5-122Bは17回でテストをすべて通しました。Claude Opus 5.5は18回すべて成功です。ただし1問の処理時間は約2.6倍（6問同時実行の条件）でした。gpt-oss-120bは最終16回成功でしたが、1回目で通ったのは11回でした。
- **同時人数**：1人から64人まで増やした負荷テストでは、応答開始までの時間は32人まで2秒以内と待たされませんでした。代わりに全員の生成速度が落ち、事前に決めた「処理時間の伸び3倍以内」の基準から、Qwenは16人、gpt-ossは8人までが実用的と判断しました。上限を決めたのはメモリではなくGPUの計算速度で、KVキャッシュの使用率は32人でも最大35％でした。
- **コーディング以外**：個人情報のマスキングや要約、翻訳の点数はClaude Haiku 5.5と同程度でした。ただ要約で議事録にないことを書き足す誤りが1件あたり0.40件と、Claude Opus 5.5の0.07件より多く出ています。

## 費用と著者の結論

B200は1時間8.04ドルで、今回の約5時間は約39ドル（約5,900円）でした。常時借りると約87万円／月で、64人で使えば1人約1.4万円／月の計算です。

著者は、コードやデータを社外に出せない、同時利用が16人程度に収まる、サーバーを運用できる担当者がいる、の3条件がそろう組織なら現実的な選択肢だとまとめています。逆に精度と速さ最優先、大規模なコード、運用の人手がない場合はClaude Codeが向いているとし、導入前に自社の課題で精度・同時人数・起動可否の3点を借りたGPUで確かめるよう勧めています。
