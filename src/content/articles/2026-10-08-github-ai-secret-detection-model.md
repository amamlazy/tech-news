## 何が出たか

GitHub は10月7日、シークレット検出のために微調整した独自モデルを発表した。周辺のコードを読んで認証情報らしきものを見分けるもので、トークンのような決まった形式を持たないパスワードも対象にする。コードや文章は生成しない。

## 提供状況

- **AI 検出のパスワードアラート**: 既存の利用者は自動で新モデルに切り替わった。GitHub Secret Protection（GHSP）と GitHub Advanced Security（GHAS）の範囲内で、追加料金はかからない
- **プッシュ保護での AI 検出**: プライベートプレビュー。プッシュの時点で形式のない認証情報を見つけ、リポジトリの履歴に入る前に取り除く機会を与える。GHSP か GHAS を購入した Enterprise Cloud または Teams が対象で、管理者が有効にする必要がある
- **Copilot の `/security-review`**: Copilot CLI と Copilot アプリで、コミットやプッシュ、レビュー依頼の前に変更を点検するコマンド。ここに分類器によるチェックが近く加わる（プライベートプレビュー）。GHSP や GHAS のライセンスは不要
- **GitHub Enterprise Server**: GHES 3.23 で AI 検出アラートがパブリックプレビューになる

## 料金の注意点

プッシュ保護と `/security-review` の新しいチェックは任意で有効にするもので、GitHub AI クレジットを消費する。課金は数週間以内に始まる予定で、GitHub は有効化の前にアクセスと支出を見直せるよう事前に告知したとしている。プッシュ保護のチェックは、プッシュをブロックしなかった場合でもクレジットを消費することがある。新しいチェックは既定でオフで、`/security-review` を実行しても自動では有効にならない。GitHub は「エージェントは明示的な許可なしに、クレジットを消費する機能を有効にしたり、ポリシーや予算を変えたりすべきではない」とも書いている。

## 現場で見るところ

`.env` に書かれた平文のパスワードのように、正規表現では拾いにくい漏えいを止められるのが利点だ。一方で課金対象になるのはプッシュ単位のチェックなので、プッシュの多いリポジトリでは費用の見積もりを先にしておきたい。
