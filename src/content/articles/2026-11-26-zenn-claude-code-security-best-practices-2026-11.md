この記事は、ゲーム会社Happy Elementsの技術ブログ（Zenn）に投稿された、筆者による実践レポートの紹介です。Claude Code（クロード・コード）は、米Anthropicが提供する、ターミナル（文字でコマンドを打つ画面）で動くAIコーディングツールで、AIが自分でファイルを書き換えたりコマンドを実行したりします。

## まず押さえる前提

筆者はまず、「Claudeに実行させたBashコマンドは、Claude Codeを起動したマシンの上で、自分のユーザー権限で動く」と強調します。サンドボックス（隔離された実行環境）をオンにしても動く場所は同じで、変わるのは「アクセスできるファイルと通信先の制限」だけだといいます。

そのうえで安全対策を2つに分けて考えます。

- **Claude Codeの設定（実行前のチェック）**：権限モード、allow／ask／denyのルール、auto mode、フック。ツールを呼ぶ前に「実行してよいか」を決める
- **OSレベルの隔離（実行中の制限）**：Bashサンドボックスや、Claude Codeごと閉じ込めるコンテナ・VM

片方で止められない操作をもう片方が止めるので、両方を有効にするのが2026年11月時点のベストプラクティスだ、というのが結論です。

## ルールの落とし穴

ルールはdeny→ask→allowの順に評価されますが、中身は文字列とパスの照合です。筆者は次のような例を挙げています。

- `Bash(curl *)` のdenyは、`/usr/bin/curl …` や `sh -c 'curl …'` を止めない → サンドボックスの通信制限で防ぐ
- `Read(.env)` のdenyは、Pythonスクリプトや `grep -r` が実行中に開く.envは止めない → サンドボックスの読み取り制限で防ぐ
- `npx` のようなツールをallowに書くと、後ろに続くどんなコマンドも許可される → パッケージや引数まで絞る

## サンドボックスの効き方

サンドボックスは `/sandbox` か設定の `sandbox.enabled` でオンにします。macOSではSeatbelt、LinuxとWSL2ではbubblewrapという仕組みが使われます。オンにすると書き込み先は作業ディレクトリなどに限られ、許可リストにない通信先は確認または拒否になります。ただし読み取りはほぼ変わらず、`~/.ssh` や `~/.aws/credentials` も読めてしまうため、読まれたくないパスはdenyルールなどに明示する必要があると注意しています。

## チェックリスト

記事には、`/status` でのバージョン確認、`/permissions` で `Bash(*)` のような広すぎる許可がないか、`claude mcp list` で知らないMCPサーバーや平文のトークンがないか、など9項目のチェックリストがあります。また、ダミーファイルを作って、サンドボックス内のPythonから読めないことを確かめる手順も載っており、本物の認証情報を使わずに設定を検証できます。
