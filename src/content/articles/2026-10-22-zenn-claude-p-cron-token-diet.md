`claude -p` は、AnthropicのAIコーディングツール「Claude Code」を、対話画面を開かずにコマンド1行で呼び出す使い方です。スクリプトや定期実行（cron）から使えて便利ですが、そのたびにAIが読む文章の量（トークン）がかかります。この記事は、yosiki氏がその量を実際に測って減らした実践レポートです。

## 何が起きていたのか

筆者は、ログインが切れていないかを確かめるだけの目的で、macOSのLaunchAgent（cronのような定期実行の仕組み）から `claude -p "ok"` を呼んでいました。ところが返事の冒頭に、普段の対話用に設定しているフックの決まり文句が毎回出ていました。つまり「ok」と返させるためだけに、個人用の `CLAUDE.md`（約2.8万字）やフック、MCPサーバー（外部ツールとつなぐ仕組み）、全ツールの定義を読み込んでいたのです。

## 実測の結果

環境はClaude Code 2.1.295、macOS、モデルはhaiku、各条件1回の計測です。

| 呼び方 | 入力トークン |
| --- | --- |
| 素の `claude -p "ok"` | 39,968 |
| ＋ `--settings '{}'` | 39,968（0%） |
| ＋ `--safe-mode` | 16,798（−58%） |
| ＋ `--tools ""` | 2,931（−93%） |
| ＋ `--system-prompt "Reply with exactly: OK"` | 737（−98%） |

内訳の目安は、CLAUDE.md・フック・スキル・プラグイン・MCPが約2万3000、組み込みツールの定義が約1万3900、既定のシステムプロンプトが約2200トークンでした。筆者は「コストを決めていたのはプロンプトの長さではなく、毎回読み込まれる文脈の量だった」とまとめています。

最終的に使っている呼び方は次の通りです。

```
claude -p "ok" \
  --model haiku \
  --safe-mode \
  --tools "" \
  --system-prompt "Reply with exactly: OK" \
  --effort low \
  --no-session-persistence \
  < /dev/null
```

## それぞれのオプションと注意点

- **`--settings '{}'`**：指定したキーだけを上書きする仕組みなので、空のJSONでは何も変わらない
- **`--safe-mode`**：CLAUDE.md、スキル、プラグイン、フック、MCPなどを読まずに起動する。ログイン（認証）はそのまま使えるのが利点。ただし本来は壊れた設定を切り分けるためのもので、将来の版で挙動が変わる可能性はある
- **`--tools ""`**：組み込みツールをすべて無効にする。ファイルを読ませたいなら `--tools "Read"` のように必要なものだけ残せる
- **`--system-prompt`**：既定のシステムプロンプト（AIへの基本の指示）を丸ごと置き換える。ツールの使い方や安全面の指示も消えるので、返事の形さえ決まっていればよい呼び出しに限る
- **`--effort low`**：返事は「OK」の2文字なのに出力106トークンのうち102が思考（thinking）だった。付けると出力は4トークンになった
- **`--bare`**：ヘルプによるとAPIキーでの認証専用で、サブスク用の長期トークンでは認証エラーになった
- **`< /dev/null`**：標準入力をつながないと3秒待った後に警告が出て、`2>&1` でまとめて受けている場合は返事に混ざり、成功判定が狂う

## 自分の環境で測る

結果をJSONで出すと `usage` が入るので、次の1行で入力トークンの合計を測れます。

```
claude -p "ok" --output-format json < /dev/null \
  | jq '.usage | .input_tokens + .cache_creation_input_tokens + .cache_read_input_tokens'
```

筆者は、対話用の設定を充実させるほど、それを使わない自動化のコストまで上がると指摘しています。7月に測ったときは素の呼び出しが37,994トークンで、3カ月で約2,000増えていたため、定期的に測り直すのがよさそうだとしています。
